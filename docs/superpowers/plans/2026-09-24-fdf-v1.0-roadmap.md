# FDF 1.0 — delivery roadmap

**Spec:** [2026-09-24-fdf-v1.0-design.md](../specs/2026-09-24-fdf-v1.0-design.md)

The 1.0 design spans five subsystems that depend on each other in order: the
foundations, the validator, the commands, `fdf migrate`, and the install,
skills and documentation. It is delivered as five plans, each written in full
once the one before it has landed, because each plan builds on the exact APIs
its predecessor creates.

The plans **expand, then contract**. Plans 1 to 4 add 1.0 beside 0.x, so every
step leaves the tests green; Plan 5 removes 0.x and ships. No release is cut
from the integration branch until Plan 5 is done.

## Branches

- **`v1`** is the integration branch, created from `claude/v1-0-design` (which
  holds the design, this roadmap and the plans) once they are reviewed.
- **Each plan** is worked on a branch off `v1` and merged into `v1` by pull
  request, once CI passes (`go vet ./...`, `go test ./...`, `gofmt -l .`
  printing nothing, and the skills' frontmatter lint).
- **0.7.1** fixes `fdf mv` for everyone still on 0.7, and is released from
  `main`. Plan 1 is done, so 0.7.1 is five of its commits cherry-picked onto a
  branch off `main`: ff7e809 (the `links` engine), 40635f6 (`fdf mv` on it),
  51abc22 (`fdf log` reads the pin as the validator does), 20bce8f
  (angle-bracket destinations) and 1546a13 (a listing found by its first
  link). None needs `specver`. Only CLAUDE.md conflicts, on ff7e809: put the
  `links` bullet after the `fdfroot` bullet. They fix these defects in 0.7.0:
  - links that leave the bundle break on a move that changes depth;
  - a footnote's first word is rewritten as a path;
  - a reference definition inside a code fence is rewritten;
  - on a moved index listing line, URLs, anchors and mail links are rewritten
    as paths;
  - a destination written as `<path>` loses its opening bracket to the path;
  - a listing line that links on to other documents stays behind when its
    document changes group, and another document's listing that mentions the
    moved one is carried off in its place;
  - `fdf log` refuses a draft's log under a single-quoted pin that
    `fdf validate` accepts.

  When 0.7.1 lands, merge `main` into `v1`. Only CLAUDE.md conflicts: keep
  `v1`'s side.
- **When Plan 5 is done**, `v1` merges into `main` and `v1.0.0` is tagged
  there.

## Carried forward from Plan 1

Plan 1's reviews left these for the plans that own them.

**Plan 2 (validator):**
- `links.Find` misses some link forms. Fix them before the validator reads
  links through it:
  - a title in `'…'` or `(…)`;
  - a `<…>` destination with spaces;
  - it matches any `](…)`, without requiring the `[` before it;
  - a code span whose opening and closing backtick runs differ;
  - a tab-indented reference definition, and inline links inside an indented
    code block.
- Export the step that decides whether a target is a path and where it points
  (`links.Resolve`), and use it in both `Retarget` and the validator's
  `resolveLink`. Reading links through `links.Find` also removes a false
  broken-link warning: the validator's own link pattern keeps a title in the
  target (`[n](x.md "Auth")`).
- `pinAtLeast(pin, minor)` in `bundle` and `scaffold` takes a 0.x minor. The
  first 1.x gate needs a signature that takes a `specver.Version`.
- Test that every `supportedVersions` key parses with `specver.Parse`, so that
  a typo such as `1.00` cannot silently fail every gate.

**Plan 3 (commands):**
- `migrate` treats only `0.4` to `0.6` as the stem layout, and relies on
  `pin == currentVersion` for 0.7. Once `CurrentVersion` is 1.0, a 0.7 bundle
  would run the pre-0.4 chain: guard it until Plan 4 replaces migrate.
- `scaffold.ListingTarget` needs `)` right after the target, so a listing
  whose own link has a title is not found by `Unlist`, `Listed`, `ListedIn` or
  `fdf mv`. fdf never writes one; decide when the commands move onto
  `layout`.

**Plan 4 (`fdf migrate`):**
- `links.Retarget` turns a link from the bundle root whose target leaves the
  new base into a relative link. Decide whether that is wanted, and test it.
- Plan 2's link-form fixes must land before migrate runs the engine over a
  whole project.
